No CLI, worker, installer, SDK, AI, examples or root documentation changes.

- `extension.New(Config, ...Registration) (*Engine, error)` validates and copies registrations, orders them and runs setup. Duplicate/reserved/invalid IDs, missing `Requires`, stage-contradicting dependencies and cycles prevent activation. `Before`/`After` refer to optional dependencies; absent targets are ignored. Ready hooks sort by stage then stable ID. IDs/owners are 1–128 bytes; `@host` is reserved. No separate check callback.
- `Registration` has `Owner`, `ID`, `Stage`, MIME `Formats`, `Requires`, `Before`, `After`, `Body`, `Failure`, `Handler`, `Setup`, `Cleanup`. Empty formats match all; otherwise parsed media type matches case-insensitively without parameters. Format mismatch is declared non-applicability, not a failed transform.
- `Handler(context.Context, Input) (Result, error)` receives detached request/response/header/body/auth/metadata/ledger/provenance snapshots. Mutating an input and passing or failing never commits it. Handlers must not modify returned values concurrently after return (the normal Go ownership-transfer contract). Trusted native code is not sandboxed.
- Stages: `Prepare`, `Resolve`, `Upstream`, `Observe` (original attempt headers or transport error), `ResponseStart` (precommit), `OriginalBody` (original bounded bytes), `ResponseBody`, `Finish` (transport-reader terminal observation), `Delivery` (external proxy-boundary observation). `Observe`, `OriginalBody`, `Finish`, `Delivery` cannot replace messages, credentials or metadata. Independent recorders own their storage rather than writing another extension's metadata.
- `BodyMode`: `NoBody`, `Whole`, `Unit`. Request Whole is available in request stages. Response Whole/Unit is available in ResponseBody; original byte observation is OriginalBody/Unit. Whole+Unit response modification in the same engine is explicitly rejected, not silently reordered. NoBody snapshots omit bytes. Request/response trailer mutation is not exposed.
- `Result{Action: Pass|Replace|Respond|Child}`. Replace requires a complete `Message` snapshot, not a patch. `Metadata` is an owner-only map replacement (nil preserves it). `Credentials` is a separate header replacement, valid only in Resolve/Upstream. Invalid outcomes honor the declared `Block` (default) or `FailOpen` behavior. Unknown actions, wrong stages, missing/invalid URLs/status/body modes and late streaming header/status edits return `ErrUnsupported`.
- `Message` contains `Method`, absolute request `URL`, `Header`, response `Status`, and declared `Body`. Request routing is request-local URL replacement, not shared proxy mutation. Credential headers are installed only after the request hook chain and are absent from later hook request snapshots. Incoming client headers remain visible; this is not credential redaction of arbitrary application data.
- `Input.Requested` preserves original request method/URL/header facts, not the original body. `Input.Request` is the accepted effective request; Observe gets original attempt response headers, OriginalBody gets bytes before presentation with detached immutable **upstream source** status/headers/MIME, not the current effective response. Its MIME applicability and ledger status use that source snapshot even after ResponseStart changes effective metadata. Only actual upstream response readers are wrapped: local/generated bytes never produce OriginalBody. A selected child's upstream observations retain the child's identity; abandoned unread parent bytes are not fabricated. A first Prepare/Whole hook can capture an original request body when needed. No original transcript persistence is supplied.
- `Input.Identity` has immutable host-generated root/exchange/parent IDs, logical attempt number and depth. `Input.Provenance` records a response-triggered child's chain as new parent input. A child runs its entire normal request/response execution (including local short circuits) and then the parent resumes after the producing ResponseStart hook. ResponseBody runs for both child and parent: non-idempotent decorators can deliberately run twice; there is no implicit hook skipping.
- `Input.Ledger` is a detached, shared-root bounded history. `@host` records upstream/local, failure, source abandonment and read-complete/read-aborted events; entries include identity, requested/served URL and status, never the credential map or body. `Truncated` explicitly reports entry/field loss. Failure outcomes use only stable categories `deadline`, `canceled`, `closed`, `overload`, `limit`, `unsupported`, or `error`; arbitrary native error/panic strings are never copied into the ledger. Successful actions retain their existing numeric outcomes and host events retain their existing labels. Outcome fields cap at 512 bytes and URL fields at 4096 bytes. This is execution evidence, not durable audit storage or a secret-inference system for arbitrary URLs, client headers or extension-provided identifiers.
- `Input.Call(ctx, *http.Request) (*http.Response, error)` executes a fresh full chain using the same underlying transport and root budget. Supply an absolute HTTP(S) URL; a child does not implicitly copy parent headers, owner metadata or selected credentials. Normal request hooks can select fresh routing/credentials. Authority is intersected with the active handler invocation independently of the supplied context (including `context.Background`). Handler return, panic, timeout or cancellation expires retained calls and cancels admitted calls/idle response bodies. Already-expired calls reject before execution admission/root budget allocation and close the rejected request body. Cancellation racing admission can still allocate an attempt, which is then canceled, not rolled back. Callers must consume/close the response before returning. `Result{Action: Child, Request: ...}` is deliberately different: the host executes that validated result after handler return under exchange lifetime, preserving the existing selection contract.
- `Engine.TrackDelivery(*http.Request) (*http.Request, func(DeliveryEvidence) error)` is the explicit boundary integration used by `proxy.NewWithEngine`. Call completion after ReverseProxy returns or unwinds; it is idempotent. `Input.Delivery` at the new NoBody-only Delivery stage contains actual final ResponseWriter status (zero if not written), accepted body byte count, first WriteError (including short writes), first FlushError, reader terminal error (EOF means read-complete), and Returned/Aborted/Hijacked flags. It is detached, observational, root-only and carries identity/provenance/ledger/owner metadata snapshots captured at Finish or execution failure. Internal child/direct-transport consumption emits Finish, never Delivery. `Input.Call` is nil at Delivery; no follow-on transport work is offered from this terminal snapshot. Completion returns observer errors; the proxy logs them via ErrorLog or the default logger, without rewriting a response or suppressing an existing panic.
- `Engine.Transport(http.RoundTripper) http.RoundTripper` decorates an existing transport, and forwards `CloseIdleConnections` when supported. `proxy.NewWithEngine(upstream, engine)` attaches it without replacing `httputil.ReverseProxy`. Existing `proxy.New` is unchanged. Additive `Proxy.SuppressInformationalResponses bool` opts **managed** proxy traffic out of upstream 100–199 forwarding, except 101, at the writer boundary before ResponseStart selection. Configure it before serving (like the embedded ReverseProxy); default false preserves existing behavior. This is a coarse external-request boundary for speculative candidates: it suppresses all candidate hints, including the eventual winner's; there is no buffering/replay or per-candidate selection API. The flag is ignored by unmanaged New. It does not suppress net/http's own inbound Expect/Continue behavior or custom private socket writes. Final headers/status/body and existing 101 forwarding/rejection contracts remain unchanged. Default target/path/query rewriting happens before extension hooks; `Input.Requested` comes from ingress before rewriting.
- `WithAuthentication(ctx, Authentication)` and `AuthenticationFromContext(ctx)` are trusted ingress integration points; claims are copied. They are not authentication protocols. `Engine.Bind(*http.Request) (*http.Request, error)` strips reserved headers, retains original facts and verifies opaque host-issued capabilities. Bind is idempotent for an already-bound host context. When an external auth middleware would reject credential-free internal HTTP, call Bind **before** it, then reuse AuthenticationFromContext; the proxy's own Bind preserves that linkage.
- `Engine.Client(ctx, gatewayOrigin) (*http.Client, error)` creates a scoped ordinary HTTP client from an active handler context. It pins the engine, issues a random capability, accepts only that exact origin, refuses redirects, and expires/cancels with the issuing handler/exchange. At most 16 live client capabilities per exchange are issued. Child ingress inherits verified authentication/root linkage, not parent upstream credentials, arbitrary headers or metadata. Issuer cancellation cancels admitted HTTP descendants too. Public forged IDs do not establish authentication; invalid capability tokens are rejected. All `X-Proxykit-*` headers/trailers are stripped at managed ingress/upstream/client boundaries. Use TLS or a trusted local hop for actual capability transport.
- `Engine.Shutdown(context.Context) error` stops admission, cancels work, waits for actual native handler exits, then cleans up in reverse registration order. A deadline stops waiting, not the native handler; Shutdown may be retried. `Close() error` waits without a deadline. Successful setup callbacks roll back in reverse order on a later setup failure. A setup callback that fails must clean up its own partial work. No reload or background job scheduler.

## Recovery, limits and transport contracts

Default Config values (zero selects these defaults): InvocationTimeout 30s; OperationTimeout 5m; Admission 64 native handlers; BodyBytes 4 MiB; UnitBytes 32 KiB; MetadataBytes 64 KiB per exchange across owner maps; LedgerEntries 256 per root; Attempts 16 logical exchanges per root; Depth 8. Negative disables the corresponding limit **except UnitBytes**, which must stay finite/positive. There is no admission queue: unavailable capacity rejects immediately with ErrOverload, including recursive calls. Admission bounds native handler goroutines, not all sockets, outstanding response bodies or deployment-wide memory.

- Whole input is retained with a hard memory cap before modification/delivery. Overflow is an error, not a fail-open attempt to replay an already-consumed unretained stream. Pass/failure retains the immediately preceding accepted snapshot. Message/owned metadata commit together only after validation; child response retention also succeeds before either commits. Child errors can fail open to the untouched parent source. Attempt ledger/budgets and external side effects are never rolled back.
- Streaming recovery is per bounded opaque byte unit. The source unit is copied for each handler and accepted replacement becomes the next handler's input. It does not roll back earlier delivered units or assemble SSE/JSON events. Output for each Unit replacement must fit UnitBytes; authors cannot assume input reads leave room for expansion. NoBody/Unit response hooks cannot change already-committed headers/status; use ResponseStart or Whole. Whole+Unit modification is rejected at startup.
- Invocation timeout discards late results, but admission remains charged until the native goroutine actually exits. Invocation return/panic/deadline and caller/operation/engine cancellation propagate to managed calls; the handler context itself is canceled immediately on return. Late callback snapshots/results are detached and discarded, and cannot apply metadata/credentials/content to the accepted exchange. Operation timeout remains active until response close/EOF and closes idle response bodies. Root attempt allocation is mutex-protected across parallel children. These are logical full executions, including denied/local calls, not provider billing or low-level connection retry counts inside `http.Transport`.
- Untouched bodies continue through the existing ReverseProxy transport with streaming/full duplex, native forwarding, live request/response trailers and upgrade handling. No semantic protocol normalization is claimed. On a 101, bidirectional bodies retain io.ReadWriteCloser and operation lifetime/drain; response-start/body/original-byte/finish/delivery hooks are explicitly rejected rather than applied to WebSocket frames. Header-only request/attempt observers are supported for upgrade handshakes.
- Local Respond enters ResponseStart/body/Finish. It ends the remaining request stages, as an explicit short circuit; protections that must cover cache/local output belong before that short circuit or in ResponseStart. Precommit Child selects the child's retained result (including selected trailers), records abandonment of the unread original source, and resumes the parent response chain. Unread abandoned original bytes are **not** claimed captured.
- HEAD/204/304 body-producing replacements are rejected. Transport failures run Observe and Finish when their context still permits callback admission, then return the error to ReverseProxy's existing ErrorHandler. Pre-dispatch/processing failures run Finish but do not fabricate an upstream attempt. ReverseProxy's generated 502 is not an extension local response and is not itself transformed. A canceled context stops new callbacks, so no guaranteed final durable callback is claimed after cancellation/shutdown.
- Finish reports effective transport-reader EOF/error/early close, **not socket-write acknowledgment or successful client delivery**. Delivery separately measures calls accepted by the external ResponseWriter: partial writes, write/flush errors and panic/ErrAbortHandler unwinding are distinct from reader completion. No remote peer acknowledgment, durable receipt, TCP delivery, header/trailer byte accounting or hijacked tunnel-byte accounting is claimed. A normal ServeHTTP return alone is not success. Input.Response is the extension-effective snapshot; Delivery.Status is the actual boundary status (e.g. an untransformed ReverseProxy-generated 502 on execution failure). The existing ReverseProxy remains responsible for disconnect/abort behavior; its panic is preserved. Informational responses remain native by default; managed proxies can explicitly suppress upstream 1xx with SuppressInformationalResponses as described above. Final delivery status excludes 1xx.
- The writer adapter delegates ResponseController full-duplex/deadlines/flush/hijack through Unwrap and preserves legacy CloseNotifier when supported; writes cannot bypass accounting via ReaderFrom. No-extension New uses no writer adapter. Upgrade forwarding with request/attempt-only hooks remains supported; Delivery hooks explicitly reject upgrades rather than pretending to account for raw tunnel traffic. Delivery hooks run with engine lifetime rather than the already-released reader context, using ordinary invocation timeout/admission and retaining a timed-out native slot until actual exit. Thus request cancellation does not by itself erase already-captured boundary evidence. Shutdown/closed admission can still prevent a callback; evidence is best-effort, not durable audit. After headers are committed, observer/transform errors can only terminate reading, not replace accepted bytes.
