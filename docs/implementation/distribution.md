Message headers are string arrays; body bytes are canonical base64 only for declared modes. Separate original attempt/source snapshots, effective response and delivery evidence exactly as native stages do. No upstream credential map appears in observational input. No arbitrary Go error/interface/function marshaling.
- Results explicitly select `pass`, `replace`, `respond` or `child`. Replacement messages are full snapshots, not patches. Optional owner metadata and separate credentials map follow native stage restrictions; child carries a bounded explicit request. Strictly reject unknown fields, malformed/noncanonical base64, missing required fields, illegal actions and oversized data. Native validation commits candidates atomically; Node failure never mutates accepted native input. Observe/originalBody/finish/delivery are observation-only.
- Whole and opaque-byte Unit data must fit both native limits and complete encoded IPC frame limits including base64/envelope overhead. Reject overflow rather than silently downgrade or accumulate unbounded streams. Per-hook/exchange/stage stream IDs and monotonically increasing safe-integer sequences distinguish concurrent streams; native sequential callbacks own per-stream ordering. Do not fabricate an EOF unit if native API only emits data; Finish separately reports completion. Never label chunks SSE events.
- Prefer bounded managed-call IPC to a second local HTTP capability service: Node context exposes a narrow managed HTTP helper, sending an invocation-correlated request to Go; Go uses `engine.Client(handlerContext, exactConfiguredGatewayOrigin)`. Keep the native capability token entirely in Go, out of snapshots/results/logs/Node-visible headers. Requests and buffered responses are explicitly bounded, redirects/unsupported modes rejected, parent cancellation expires the call, and unknown/expired invocation IDs cannot authorize reuse. Full ordinary gateway chains and shared root budgets apply; recursive capacity rejects rather than waits. Delivery has no managed-call helper. Arbitrary trusted Node networking remains unmanaged. If worker callback mechanics or core seams cannot satisfy these rules, report the concrete blocker rather than weakening them.
- Activation lists validated records, starts each trusted process with explicit limits/config/logging, validates every descriptor and constructs one engine. Any failure rolls back all started workers; no installed package is silently omitted. Shutdown stops public admission, drains/cancels the engine within bounds, then stops/reaps workers and closes transport resources. ## Installation contract

`proxykit extension install <https://github.com/owner/repository[ /tree/revision ]> --trust` acknowledges arbitrary server-side code execution on later server activation. The concrete parser may restrict revisions to an unambiguous single URL segment; diagnostic must explain that restriction. No implicit trust, package-manager invocation, shell interpolation, build hooks or install scripts. Accept prebuilt dependency-free ESM only; Node builtins and relative bundled modules are allowed. GitHub ownership and manifest declarations are not evidence of safety. Trusted code can access the server's filesystem/network/identity.

Root `proxykit-extension.json`: strict JSON object with `manifestVersion: 1`, `id` (lowercase safe identifier), `version` (explicit package version), `entry` (relative `.mjs` path). Reject unknown fields, invalid IDs/versions and absolute, dot-dot, symlink/hardlink/special-file archive paths. Resolve the selected ref/default branch to an immutable 40-hex commit before downloading its archive. Record source URL and resolved commit in host-owned provenance, never trust archive-supplied provenance. Bound download/extracted sizes and file counts. Stage in the destination filesystem, validate fully before atomic publish, leave a prior install intact on failure; prefer refusing overwrite initially if atomic updates cannot be kept simple. List reports provenance; remove validates ID and store containment. Changed registrations require server restart; CLI says so explicitly. Local fake GitHub HTTP/archive fixtures exercise production validation without credentials/live packages.

## Public worker protocol v1

Transport: stdin/stdout, unsigned 32-bit big-endian byte length followed by UTF-8 JSON. Default maximum frame 1 MiB; reject zero/oversize lengths before allocating body. The initial `init` frame is additionally capped at 1 MiB before negotiation. Frame bounds include the complete JSON envelope, not just a body field. Default concurrency is 16 (accepted configured range 1–4096); accepted frame range is 256 bytes–64 MiB. Stdout is protocol-only; SDK logging and standard global console methods go to stderr. Direct extension writes to stdout are unsupported and fail the process protocol. All frames carry `v: 1` and `type`; request/reply frames carry unique string `id`. Unknown versions, malformed messages and unmatched non-late replies terminate the worker and fail pending calls.

Handshake: host sends `init` with extension entry/configuration and negotiated positive frame/concurrency limits; runtime imports trusted ESM, calls its default setup function, then returns `ready` with stable hook descriptors. Registration closes when setup completes. Descriptor fields: `id`, `stage`, `bodyMode` (`none`, `stream`, `buffered`); optional `order` is a finite numeric value. IDs and stage labels match `[a-zA-Z][a-zA-Z0-9_.-]{0,127}`. At most 4096 hooks may be registered. Stage labels are deliberately not Group A enums. Stage is a bridge-consumed label, not a second Go execution engine. Validate duplicate IDs and shapes before readiness. Setup receives `on(descriptor, handler)`, logging, lifecycle cleanup registration and configuration. Hooks receive JSON input and context with `AbortSignal`; return a JSON result. No separate check callback; an explicit pass result leaves input untouched.

Invocation IDs are host-generated positive decimal strings (at most 20 digits), never reused across explicit restarts of a Worker object. Invocation: `invoke {id, hook, input, deadline?}`; reply `result {id, output}` or `error {id, error:{code,message}}`. Deadline is an absolute Unix millisecond timestamp. Host `Invoke(ctx, hookID, input)` checks bounded concurrency without an unbounded queue; cancellation sends `cancel {id}`. Reject late output. Keep capacity charged until the handler settles or the process is terminated; cancellation does not undo external side effects. Runtime must retain cancelled work in its active count. Default call timeout 30 seconds, configurable. A bounded grace may kill an uncooperative worker; process death fails all outstanding calls. No automatic replay of calls. Restart is explicit and returns freshly validated registrations; the bridge must not silently substitute registrations for active requests.

Streaming: only explicitly supplied bounded units cross IPC, never automatic whole-body copies. Stream hook input uses `{streamId, sequence, data, end}` with base64 bytes; one call per bounded unit, sequential per stream as enforced by the caller. A buffered body must fit the negotiated frame bound. Host bridge will own body retention, commit semantics and serialization; this package does not claim HTTP rollback.

Shutdown: atomically stop admission and enqueue one `shutdown` after all admitted invocations, cancel/drain outstanding calls within a configured deadline, run registered cleanup, reply `stopped`, then exit. Concurrent Stop callers join the same shutdown; no duplicate shutdown or late invoke/cancel frames are sent. Kill after deadline; reaping may finish asynchronously after a timed-out Stop returns. A successful Stop requires a stopped acknowledgement, a clean process exit and completed pipe forwarding; cleanup exceptions, protocol failures, missing acknowledgement and forwarding failures return errors. Startup failures and malformed output are actionable errors, never permission to ignore a required extension. Stderr is forwarded to an explicit logger/writer and does not carry protocol frames.

## Implemented Go APIs and layout

- `extensions.Installer{Store, Client, APIBase, ArchiveBase, MaxDownload, MaxExtracted, MaxFiles}` supplies `Install(ctx, source, trust) (Installation, error)`, `List() ([]Installation, error)` and `Remove(id) error`. Endpoint overrides are for local/private fixtures; production CLI always uses default GitHub HTTPS endpoints and an HTTP client timeout of 60 seconds. No Git, shell, npm, install/build scripts or package execution occur during installation.
- Default compressed download limit is 16 MiB; extracted regular payload limit is 64 MiB; archive entry count and actual package filesystem object count are each limited to 2048 by MaxFiles. The object budget includes implicit parent directories and regular files, counts each path once, and is checked before creating any parents for an entry; the package extraction root and fixed host staging/provenance objects are not archive objects. Raw gzip expansion (including metadata/padding/trailing streams) is additionally capped at `MaxExtracted + MaxFiles*2048 + 1024` bytes and checksum-validated. These are finite default limits, not a sandbox against trusted code after activation. JSON manifest/provenance files are capped at 64 KiB. Paths are capped at 4096 bytes. Archive permissions/ownership/timestamps are not restored: directories are 0700, regular files 0600. Sparse archives, duplicate paths, mixed archive roots and directory payloads are rejected in addition to links/devices/FIFOs/traversal.
- Root manifest fields are exactly `manifestVersion`, `id`, `version`, `entry`. Unknown/duplicate JSON keys and non-UTF-8 JSON are rejected. IDs match `[a-z][a-z0-9-]{0,63}`; versions are SemVer-shaped strings of at most 128 bytes, with proper numeric leading-zero and nonempty identifier checks. Entry must be a safe relative `.mjs` regular file. This accepts prebuilt dependency-free ESM and bundled relative modules; dependencies are never fetched or compiled. It does not statically prove a trusted module's import graph or restrict its later filesystem/network behavior.
- GitHub `git archive`-style PAX global **comment-only metadata** is accepted and ignored, never extracted. Any global PAX path/other directives are rejected. Per-file PAX/long-name resolution is performed by Go's tar reader before path/type validation. This is not permission to extract special files or trust archive-provided commit comments.
- Layout is `<store>/<id>/installation.json` (host-owned provenance) and `<store>/<id>/package/...` (archive content). Manifest content cannot overwrite host provenance. Install locks the store using `.lock`, stages under a hidden directory on that filesystem and atomically renames only after complete validation. Reinstall/update refuses an existing ID; remove then reinstall is explicit, not an atomic update promise. Failed replacements leave the prior install intact. This guarantees atomic visibility, not power-loss durability. A process crash may leave a hidden stage or `.lock`; an operator must inspect/remove stale lock/stage directories before retrying. The store and its ancestors must be host-owned and not externally modified concurrently. Store/installed-root symlinks are refused; Remove does not follow descendant symlinks.
- CLI store: `PROXYKIT_EXTENSIONS_DIR` override, otherwise `os.UserConfigDir()/proxykit/extensions`. `extension list` emits JSON including source and immutable commit; install/remove explain restart requirements. Serving validates installed records and activates their workers/hooks before accepting HTTP traffic; malformed records fail explicitly. No-extension transport is unchanged.
- `worker.New(Options) (*Worker, error)` exposes `Start(ctx) error`, `Hooks() []HookDescriptor`, `Invoke(ctx, hookID, json.RawMessage) (json.RawMessage, error)`, `Stop(ctx) error`, `Restart(ctx) error`. `Hooks()` returns a copy. Options include `NodeBinary`, absolute-resolved `Entry`, JSON `Config`, explicit `Stderr io.Writer`, `MaxFrame`, `Concurrency`, `CallTimeout`, `StartupTimeout`, `CancelGrace`, `ShutdownTimeout`. Zero values choose defaults: node on PATH, 1 MiB, 16, 30 seconds, 10 seconds, 1 second and 5 seconds respectively. Negative timeouts/invalid bounds are refused. Keep the stderr writer responsive: ordinary `os/exec` stderr forwarding has backpressure, not an independent durable logging queue. Cmd.WaitDelay is 20 ms to bound inherited stderr pipe completion after direct-child exit; an inherited stdout descriptor gets a separate 20 ms final-frame drain allowance. WaitDelay cannot interrupt arbitrary user Writer.Write code. Even with a blocked user writer Stop returns at its deadline, but the copier/reaper may remain alive until Write returns; do not reuse/read an unsynchronized writer before reaping finishes. Descendant processes are not sandboxed or process-group killed.
- Startup errors require `Stop`/`Restart` before another `Start`; no call is replayed. Admission is immediate (`worker.ErrBusy`), with a bounded write queue. Canceled calls retain their slot until the matching result/error settles or the process is killed after grace. Late results are discarded and release only their own slot. Stop refuses new admission and promptly returns cancellation to active Invoke callers, while cleanup/draining is bounded by shutdown timeout/context. Invoke marshals before admission, then registers/enqueues under one lock shared with shutdown. Cancellation enqueue is ordered under that lock too. Stop initiates shutdown once and retains its error/ack/exit outcome for repeated callers until a new Start. Each caller can impose a shorter context deadline (which kills the shared process). Start and Restart are serialized. Restart joins an in-progress Stop and never overlaps an unreaped process; after a Stop deadline it may require retry once reaping completes. A shutdown failure discovered during Restart is returned; a deliberate later Restart can replace an already-failed process without replaying calls. Prior failures are never permission to skip required hooks.
- `sdk/index.mjs`, `sdk/index.d.mts`, and `sdk/README.md` define ESM helpers, declarations and author guidance. `examples/node-personal-usage/` is a prebuilt dependency-free HTTP-hook example; the compiled CLI activation fixture exercises the installed-worker path. TypeScript authors must explicitly compile/bundle before packaging.

## Exact frame shapes and runtime details

Every shape below includes `v:1` and no extra top-level keys. `output`, `input` and `config` may be any JSON value; a returned `null` is meaningful, while missing/undefined output is not. The host rejects malformed UTF-8, duplicate JSON keys, unknown fields, wrong shapes and unmatched replies. Runtime validates host message fields and version before dispatch.

```text
host -> {v:1,type:"init",entry:"/absolute/extension.mjs",dataDir:"/absolute/store/.data/example",config:{},maxFrame:1048576,concurrency:16}
node -> {v:1,type:"ready",hooks:[{id:"example",stage:"observe",bodyMode:"none",order:0}]}
host -> {v:1,type:"invoke",id:"1",hook:"example",input:{},deadline:UNIX_MILLISECONDS}
node -> {v:1,type:"result",id:"1",output:{action:"pass"}}
node -> {v:1,type:"error",id:"1",error:{code:"HOOK_ERROR",message:"..."}}
host -> {v:1,type:"cancel",id:"1"}
host -> {v:1,type:"shutdown"}
node -> {v:1,type:"stopped"}
```

`dataDir` (absolute when supplied; empty/omitted for generic workers), `order` and `deadline` are optional; all other illustrated fields are required. Error codes emitted by the runtime are `HOOK_ERROR` and `CANCELLED`; host treats a nonempty code/message as an invocation error, not a successful pass. Startup/setup/protocol failures log stderr and exit nonzero rather than inventing an undocumented startup-error frame. Cancel for already-settled work is harmless (it may race result delivery). A worker-originated reply for an ID no longer pending is a protocol failure, not an unrestricted late-result allowance. Duplicate readiness/stopped frames are failures. A stopped acknowledgement is permitted only during host shutdown after pending results have settled.

Setup receives `config`, `on(descriptor, handler)`, `log(...args)` and `cleanup(fn)`. Async setup is awaited; registrations then close. Cleanup functions run in reverse registration order after active handlers settle. The runtime does not call a handler whose invocation deadline has already expired; an active handler receives a signal and must cooperate. Cancellation does not force a Promise to settle and does not undo side effects. The host kills an uncooperative process after grace. A cleanup function that hangs is also subject to host shutdown kill. All normal global console methods (including table/count) are redirected to stderr before module import. Direct stdout writes or constructing a separate stdout logger remain unsupported trusted-code behavior.

Stream envelope: `{streamId:string,sequence:nonnegativeSafeInteger,data:canonicalBase64,end:boolean}`. SDK stream helpers bound decoded bytes (64 KiB default) and reject malformed/noncanonical base64. IPC bounds include base64 overhead. Generic `Invoke` is not a stream scheduler: the bridge must ensure sequence/stream identity and one in-flight unit per stream. Neither worker nor SDK automatically retains an HTTP body, copies all request history or promises rollback after HTTP commitment.

## Round 3 implemented activation bridge

`nodehost.Open(ctx, Options) (*Host, error)` validates installer records, starts real workers, checks every descriptor and builds one native engine. `Host.Engine` is passed to `proxy.NewWithEngine`; `Host.Engine.Bind(handler)` validates managed scope before ordinary middleware/authentication; `Host.Close(ctx)` first shuts native admission/drain, then workers. Failed startup rolls back every worker it started with a separate bounded cleanup context, preserving errors. `Options` supplies Store, exact Gateway, Worker options (NodeBinary, Stderr, Config and worker bounds), and Engine config (including BodyBytes/UnitBytes). Node workers and native handlers retain separate capacity ownership; no core edits or extra execution engine.

CLI retains `proxy.New` when the validated startup list is empty. Otherwise it opens the host, uses NewWithEngine, wraps Bind and supplies worker configuration `{gatewayOrigin}`. New `-node` and `-gateway-origin` flags are explicit. The configured origin defaults to the actual listener address, including port-zero allocation; HTTPS follows existing TLS configuration. The socket is bound to establish that address before worker setup, but **HTTP Serve/Accept does not start until all activation validation succeeds**; failure closes the socket. Thus the proposal's “before listening” means before HTTP admission, not before binding a TCP port. No request can execute a partial registry. Public shutdown precedes native drain/worker shutdown; transport cleanup uses an interface assertion rather than assuming every RoundTripper is *http.Transport.

### Wire, author API and limits

The original invoke/result protocol is extended with optional host invoke flag `managed:boolean`, strict versioned Node `call {id,callId,request}` and Go `callResult {id,callId,output|error}`. All envelopes carry v:1. Both IDs are positive decimal strings. Each invocation may issue only one outstanding callback; callbacks require a live explicitly authorized invoke scope (`InvokeWithCallback`, not ordinary Invoke). One bounded global callback slot per worker concurrency slot, bounded complete request/response frames, bounded error encoding and actual callback settlement own capacity. Unknown scope/correlation, duplicate call IDs, unknown keys/versions and forged callbacks fail the worker. A correctly correlated in-flight call for a still-known cancelled/context-dead authorized scope is discarded without callback execution or process failure; a removed/unknown scope is not authorized by this exception. Late cancelled known results are discarded. Callback capacity exhaustion returns a bounded correlated callResult error, not a process failure; actual callback execution and response preparation settle before releasing capacity, and release precedes result visibility. Runtime rejects a settled helper, clears outstanding callback promises on settlement/cancel/shutdown, and never attaches a helper for delivery or a generic invocation. Go independently rejects delivery scopes. The Go handler uses engine.Client(activeContext, exactOrigin), bounded body reads and no redirects; capability headers/tokens are never serialized. A bind-once wrapper prevents implicit skipping of authentication. It does not install authentication where none exists.

Descriptors add optional failure/formats/requires/before/after consistently in Go/runtime/SDK; Hooks and runtime registration take defensive slice copies. Numeric order is translated into deterministic same-stage priority edges, not ignored. Required dependencies must exist; unknown optional before/after targets are ignored; contradictory order, dependency cycles, cross-stage contradictions, invalid global IDs, stages/modes/formats and mixed Whole/Unit response transforms refuse activation. At most 64 workers and 512 hooks activate. No hot swapping or auto-restart/replay.

`defineHTTP`, typed inputs/results, `pass`, `replace`, `respond`, `child` and stream helpers are dependency-free ESM+TS author APIs. See `sdk/README.md` for exact allowed stage/action/mode combinations, namespace/dependency syntax and executable example. Full snapshots encode canonical base64; explicit string error fields replace Go error interfaces. Strict result validation rejects unknown/duplicate/null fields, malformed base64, missing fields and invalid HTTP header names/values/string arrays (including null-to-empty coercions).
