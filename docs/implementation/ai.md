# Group C: optional AI runtime, managed-host bridge and recall

## Status and ownership

Implemented, not universal client/provider certification. This round changes only `ai/`, `examples/recall/`, new `examples/aihost/`, and this document; standard library only, no dependency/core/host/SDK/CLI changes and no commit. The earlier reviewed foundations and four correction groups remain in place. The manager's previous full-repository validation is historical; the validation below is this round's focused evidence. Manager independent review and full race/vet/build remain precommit gates.

The actual bridge is optional. Ordinary forwarding does not require the AI runtime, recorder, conversation store or tool coordinator. `examples/aihost` is an importable application wrapping an existing ProxyKit handler, not a second proxy, new listener framework, broker or credential subsystem.

## Implemented contracts

### Host registration, wire evidence and required recording

- `ai.HostManaged` implements `Managed.Call` using a scoped `extension.Input.Call`. The application constructs it **inside** its owned `Prepare` registration; it creates no raw HTTP transport/client. All classifier, candidate, reroute and continuation calls use that Session and thus reenter the registered host pipeline with the current root's authentication, authorization, cancellation and attribution. Credential refresh, destination policy and signing remain registered host/application responsibilities on **every** child call. This trusted-code API cannot detect an application intentionally supplying an unrelated callback or making private sockets.
- `ai.HostRecorder.Registrations` installs separate `Observe` and `OriginalBody` handlers. They capture the actual effective host request, original upstream status/headers/body and host `extension.Identity`. They never use `ResponseBody`, a decorated returned body or local response bytes as original evidence. `Attempt.Logical` and `Caller` correlate logical Session lineage/trusted identity with physical host identities; a restart preserves logical lineage but begins a new HTTP root. A scoped private context key prevents unrelated ordinary traffic from being buffered by this recorder.
- `HostRecorder.Evidence` must map the **post-routing** `Input.Request` to trusted account/protocol/catalog evidence. It must not echo the desired input target: endpoint equality and nonempty account/protocol are checked; response model is decoded from actual upstream output, not guessed from requested model. Deployment code owns correct catalog evidence. Missing/ambiguous provenance, missing actual model, local-only results, unknown protocol/MIME and multiple original sources in one call fail explicitly. This bridge deliberately does not guess a retry winner or normalize opaque nested broker attempts; multiple sources are recorded but rejected for selection.
- Actual bounded JSON / `text/event-stream` is decoded through the registered `Protocol` / `StreamingProtocol`. Both built-in Chat and Messages adapters are supported. The returned decorated body is drained with its own bound to complete the host body lifecycle but never used for source decoding. Original capture defaults to 4 MiB per managed call; overflow stops consumption and records only the observed prefix. `Attempt.Complete` describes source consumption, not successful semantic decoding or peer delivery. Partial/error attempts retain unknown usage, not manufactured zero.
- Required `AttemptSink(context.Context, []Attempt) error` is awaited before **any** managed result can become a logical success or selected client response. Sink input is detached; failure denies final delivery. Persistence gets a separate five-second context even after caller cancellation. The sink must honor that context; trusted Go code cannot be forcibly stopped. No required recording relies on best-effort `Finish`. The socket fixture uses synchronous file append + fsync; that fixture is evidence, not a production outbox.
- Three boundaries remain distinct: original `ai.Attempt`, logical `ai.Observation` from `Session`, and the existing host's external `extension.Delivery`. Failed/losing calls are not client deliveries. This implementation neither invents a successful delivery acknowledgement nor treats persisted logical success as proof the client received bytes.

### Application and commitment

`examples/aihost.App.Handler` runs after trusted authentication middleware has installed `extension.Authentication{Subject, Claims["tenant"], Claims["conversation"]}`. It buffers **only** the exact configured POST path, with a 1 MiB default request bound; all other paths pass directly to the existing handler. No tenant, conversation, caller, Turn, endpoint, affinity, credential or owned tool implementation is accepted from the JSON body/tool arguments. The revision header is only an untrusted CAS token. Supported ingress is an explicitly narrow Chat text/function-tool subset; unknown request/message/tool fields and provider-held continuation IDs are rejected rather than discarded.

`App.Registration` coordinates only that marked root request. It verifies host authentication again, installs validated owned tool definitions separately from client tool declarations, obtains revision admission, classifies/selects through the scoped Session, continues tools, persists private state/budgets, then returns an existing host **local response**. Hook ordering/policy dependencies are deployment-owned registration choices, not caller controls. An installed blocking policy must be ordered before the relevant operation; this example does not silently install an approval policy.

`Handler` supplies a selection writer that withholds all headers until final selection/error, including clearing/discarding informational responses. This matters because managed children can inherit the standard reverse proxy's parent `httptrace` callback. Only final selected Chat JSON/SSE headers/bytes are delivered; provider headers, early hints and raw private tool results are not forwarded. Commitment does **not** depend on a caller-supplied boolean. Existing `ai.Reroute(..., committed)` remains a low-level helper for trusted callers, not the application's socket commitment authority. Buffering is confined to declared coordination paths; an actual ordinary socket response delivers its first flushed bytes while the upstream is still open.

The concrete composition/registration example is `examples/aihost/app_test.go:gateway`: existing Engine + transport + authenticated middleware + app registration + independent recorder registrations + separate presentation registrations. Authorization and fresh credential material are applied in child Resolve hooks. The fixture broker intentionally changes `/broker` into `/messages`; original evidence and persisted served affinity resolve `/messages`, not the requested endpoint. Both original-body and final-client presentation edits are exercised independently.

### Tools, trusted identity and durable continuation

- `Coordinator.Validate` is an optional application pre-effect validator. All selected call IDs/arguments and **all** selected application tool validations finish before any owned tool runs. The host example requires a strict validator for every owned tool, rejects declaration collisions/undeclared calls/non-object arguments, and its fixture validator rejects identity/Turn extras. Speculative candidate results cannot execute tools. Application validators own schema/authorization semantics; this is not a generic JSON-schema engine.
- `Coordinator.Start` / `Resume` preserve public replay, private working history, ordered IDs/results, mixed owned/client handoff, stable trusted `ToolCallID(ctx)` and cumulative rounds. Owned effects do not rerun on a normal completed handoff/restart. Tool identity comes from trusted context, never model arguments. Replay must match the exact public prefix plus each pending client result once. Optional context reduction changes only private working input: the public replay prefix remains the durable original client history.
- `recall.Store.Archive` commits original material and a usable unreduced working copy before `Reduce` executes. The optional host reduction test reads the actual durable archive from inside the reducer. One compactor owner and tenant/conversation CAS revisions prevent cooperating conflicting reductions and replay winners.
- `recall.Store.Run` commits an `InFlight` reservation **before** inference/tool effects, releases the file lock while trusted work runs, then CAS-commits Turn, working state, actual served affinity and `ai.Budget` together. Every mutation rejects an existing reservation. Errors/crashes leave it quarantined with `ErrUncertain`; there is no automatic retry/reset/lease expiry. This intentionally sacrifices availability rather than replaying an uncertain owned effect or pretending an uncertain admission cost is zero. External effects are not filesystem-transactional or exactly once. Recovery/reconciliation needs application-specific operator/idempotency logic and is not implemented.
- `Session.Budget` requires no active work and captures root, cumulative calls/tool calls/output charges and limits. `RestoreBudget` requires an unused Session with identical effective limits and rejects invalid snapshots. `App` persists a total continuation deadline (default five minutes), restores counters before admitting any continuation work and preserves the same deadline across requests/processes. Host root limits still apply separately on every HTTP root. Changed limits, expired lifetime and legacy Turn files without an authoritative budget reject safely rather than resetting. Negative Session bounds retain their explicit opt-out semantics; the app's durable lifetime stays finite.
- `Store.Continue` now uses the same durable reservation gate and restores its saved budget into an unused coordinator Session; it preserves a saved deadline. `SaveTurn(..., turn, budget)` is a quiescent checkpoint API, **not** effect-safe read/run/save admission: callers must supply the authoritative snapshot. Use `Run` / `Continue` before effects. Existing checkpoints missing budgets are not silently resumed.

## Protocol foundations and preserved corrections

`Managed` remains the inference abstraction; `Protocol` / optional `StreamingProtocol` are registration seams without a universal provider registry. `Usage.Input` / `Output` are pointers: nil is unknown, pointer-to-zero is measured zero. `Request.Requested`, selected `Target` and actual `Result.Served` remain separate. Classifier labels are allowlisted, not model-provided destinations. `Prepare` checks built-in capabilities/settings and explicit affinity migration; `Candidates` bounds fan-out, cancels losers and waits for their work to end; `CacheKey` scopes tenant/conversation/account/route/revision, but no cache implementation is supplied.

Supported semantics remain one choice, text and ordinary JSON function/tools. Same-wire `Document`, root edits, retained unknown fields and explicit unchanged passthrough are not permission to flatten unknown state. Signed reasoning, opaque/provider-held references, unknown stream semantics, unsupported ordering, multimodal/server-tool histories and model truncation reject conversion/migration. SSE defaults remain 4 MiB total, 256 KiB/event and 10,000 events. It is complete bounded stream selection, **not** live semantic transformation.

The manager's four prior corrections are preserved and rerun:

1. Strict Anthropic message/assistant/terminal envelopes and object tool inputs before tool effects.
2. Chat SSE `system_fingerprint`/`service_tier` retention and rejection of unsupported cross-wire/synthetic conversion; event evidence retained even on semantic errors.
3. Strict known-field types and malformed SSE fragment/index/usage/envelope rejection rather than normalization.
4. Cancellation recheck after observer/output accounting, preventing late successful return.

`ai/correction_test.go` still exercises these through `TestWireEnvelopeRejectsBeforeOwnedTools`, `TestBufferedStreamUnknownEvidenceAndMetadata`, `TestMalformedKnownWireFields`, `TestObservationDeadlinePreventsSuccess`, and `TestUsageEditsAndNonfiniteSettings`. Nil/zero/replaced usage totals and NaN/infinite settings checks remain unchanged.

### Focused bridge evidence correction, round 2

`examples/aihost/bridge_evidence_test.go` adds real-host regressions without changing production behavior:

- `TestSocketRequiredRecordingFailureAtSelectedAndResumedInference` permits successful classifier recording, then targets required sink failure or a 1 KiB capture bound at the selected tool-producing inference. Both modes also run after a successful mixed-tool handoff: the prior owned effect remains, but the failed resumed response adds no effect. Assertions cover error-only client delivery, unchanged successful Turn checkpoint, durable `InFlight` quarantine, and no upstream admission on replay with either the old or persisted revision. This closes the phase gap in the earlier always-failing-sink/32-byte tests, which failed at classification.
- `TestSocketNestedResponseReplacementRejectsMultipleOriginalSources` uses a response-body hook's actual nested `Input.Call`, reads the nested response and replaces the parent body. The required fsynced sink receives two original bodies with the same logical lineage but distinct parent/child host exchanges inside **one** selected `HostManaged.Call`. The logical error specifically contains `ambiguous multiple upstream sources`; no owned tool or successful selected output escapes, and the request remains quarantined. This is not candidate fan-out: the existing candidate test makes separate logical calls, each with one original source. Multiple-source selection remains unsupported.

Executed for this evidence round: `go test ./ai ./examples/recall ./examples/aihost -count=1` and `go test -race ./ai ./examples/recall ./examples/aihost -count=1`, both exit 0. Full repository gates remain the manager's responsibility.

## Exact limitations and remaining integration gates

- Use `App.Handler` **and** the app/recorder registrations together; wrapping an Engine without installing the recorder fails closed, not a working managed bridge. Authentication middleware and route/credential/evidence hooks are required. The package adds no stock broker, authorization database, policy order, account refresh service or application listener binary. Trusted hooks may not rewrite identity or fabricate catalog evidence.
- Default Session bounds remain 16 model calls, 32 tools, 8 rounds, 4 active functions, 1 MiB cumulative logical output and 30 seconds per call/coordinator invocation. The app also has its finite durable lifetime and wire bounds. These do not bound arbitrary allocation or CPU in trusted callbacks. Required recorder capture occurs only after its hooks receive evidence; it cannot recover bytes lost before observation.
- Managed source decoding rejects unsupported/malformed outputs before tools. Unknown provider usage stays unknown; there is no pricing/reservation estimator or claim to accurate billing. A partially read failed source may have no usage. Oversized sources retain a bounded prefix, not fabricated full evidence.
- Filesystem persistence needs a private/trusted directory, local same-directory atomic rename, advisory flock and file/directory fsync. Linux is exercised; existing platform gates cover Linux/macOS/FreeBSD and reject unsupported mutation platforms. No NFS/multi-host topology, encryption, retention/GC, power-loss fault injection or lock-fairness claim. Archive/file bounds remain finite; originals are not silently evicted.
- A durable logical checkpoint can precede socket disconnect or later presentation failure. The same completed client handoff replays correctly; an already-completed final-response retry has no delivery-cache/recovery API and rejects. Do not describe this as exactly-once delivery.
- No missing core API blocks this bounded single-source slice. A generalized bridge across nested broker retry/replacement sources would need an authoritative host-selected-source identity plus actual served account/protocol/request provenance; this implementation explicitly rejects that ambiguous case instead of modifying Group A. Production multi-source selection, installed policy ordering, lifecycle/drain, durable sink integration and manager full-repository review remain integration gates.
