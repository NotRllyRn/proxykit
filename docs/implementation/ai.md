# Group C: optional AI and state application examples

## Plan (implementation authorized; not yet acceptance evidence)

Ownership: `ai/`, Go `examples/` subpackages excluding `examples/node-*`, and this document. Do not modify transport, extension host, worker/installer/SDK, CLI, root documents or module dependencies. Use standard library and small explicit contracts, not another proxy or a general workflow framework.

1. Define an injected managed inference interface and detached original attempt observations. Parent integration must bridge every call through Group A's applicable authentication, request/response hooks, lineage, budgets and final delivery. Preserve requested versus served routes and missing usage versus measured zero.
2. Implement a protocol extension interface with OpenAI Chat Completions and a narrow Anthropic Messages slice. Preserve raw unknown fields on same-protocol round trips; reject unsupported cross-protocol semantics (especially signed reasoning, provider-held references and opaque content). Add bounded SSE event parsing, valid incremental/final representations and truncation handling. Clearly distinguish buffered selection/continuations from live delivery.
3. Implement optional owned tools/coordinator: unique call IDs, duplicate tool names, mixed client/internal handoff, trusted context separate from arguments, private continuation transcript, nonstream/stream paths, cancellation and configurable round/call/parallel/output/time limits. All inference uses the injected interface. Never execute tools from an unselected speculative candidate.
4. Build a durable recall example with explicit tenant/conversation keys, archive-before-reduction and transactional compare-and-swap revisions. Standard-library atomic file persistence is acceptable with honest topology/durability limits. Prove fresh-process restart, replay/private continuation reconciliation, concurrent conflict and tenant isolation. Preserve or explicitly reject signed/provider-held state; never silently remove it.
5. Add target capability/settings translation, precommit reroute and bounded candidate helpers, cancellation of losers and original outcome accounting, affinity/migration checks and cache scope keys. Authorization/credential binding belongs to the injected managed host; demonstrate the boundary with fixtures, not a second credential subsystem.
6. Add combined coordinator + replay/restart + reroute fixtures and independent original observations. Review source/diff and run unit/integration tests, race detector, vet and build. Send concrete defects to fresh correction tasks carrying prior findings. No commit in this initial round; wait for manager review and explicit follow-up.

## Evidence and integration needs

### Round 1 implemented slice (not acceptance of the full requirements)

All code is standard-library-only. Added `ai/` and the importable Go application example `examples/recall/`; no HTTP client, transport, credentials subsystem, second proxy, module dependency or production dashboard/broker was added. Manager source review and independent validation completed after correction round 2; see the final review evidence below.

**Inference/observation API:** `Managed.Call(context.Context, Request) (Result, error)` / `ManagedFunc` is the only model boundary. `Session.Call` performs local shared admission, cancellation/late-result checks and synchronous detached `Observer(context.Context, Observation) error` handoff before returning a result for presentation. An observer error fails closed. `Request` separates authenticated `Identity` from model messages/arguments and immutable-by-copy `Requested` from selected `Target`; `Result.Served` is the managed bridge's authoritative actual destination. `Usage.Input`/`Output` are `*int64`: nil is unknown, a pointer to zero is measured zero, including in failure fixtures. `Lineage` carries logical root/parent/call IDs; `Session` generates distinct local call IDs, binds one root and rejects a conflicting root. Cooperating users share one Session. Configure exported limits, bridge, observer and tool maps before concurrent use; callbacks must be concurrency-safe.

**Protocol API:** `Protocol` and optional `StreamingProtocol` have no registry dependency. `Adapter{Kind: Chat}` and `Adapter{Kind: Messages}` support a single text/tool answer and constructed semantic message histories with JSON tool arguments. `EncodeRequest` translates function/tool schemas and token/temperature settings into the target wire form. `Document` is the explicit same-wire root-field escape hatch for request instructions/tools or unknown fields; it does not import arbitrary histories. `Response` retains original JSON, unknown root fields and opaque content; `Passthrough` explicitly returns unchanged original bytes. Same-wire ordinary encoding retains unknown root/usage fields and known metadata. Signed/unknown nested blocks, unsupported ordering and nonportable state are not flattened. Cross-wire encoding and synthetic streams require `Portable` state. `ReadEvents` / `WriteEvents` retain event data, unknown fields, IDs and comments (not byte-for-byte line order); semantic decoding returns the retained events even when unsupported. SSE is bounded by default to 4 MiB total, 256 KiB/event and 10,000 events. Missing terminal/finish markers, partial events, malformed arguments, invalid indices and truncated model completions are rejected. `EncodeStream` emits actual text/tool deltas, terminal markers and available usage, not ordinary final JSON disguised as a stream.

**Coordinator API:** `Coordinator.Start` / `Resume` return a private serializable `Turn` with public replay, private working transcript, pending client IDs, already-executed internal results, logical lineage and cumulative rounds. Duplicate tool names with distinct IDs are supported; duplicate IDs fail before effects. Mixed output hands off only unresolved client calls and privately preserves internal calls/results. Resume requires exact public replay plus each pending client result once, then merges all results in original call order. `Tool(context.Context, Identity, json.RawMessage)` receives trusted identity separately; `ToolCallID(ctx)` exposes the stable trusted call ID for application idempotency. Fixed tool workers, shared Session parallel admission and cancellation stop queued work. Default bounds are 16 model calls, 32 tool calls, 8 rounds, 4 concurrent model/tool functions, 1 MiB accumulated encoded-response/tool output and 30 seconds per coordinator invocation / managed call; individual negative values explicitly disable those local bounds. Candidates never invoke tools.

**Recall API:** `recall.Store.Read`, `Archive`, `Reduce`, `SaveTurn` and `Continue` use explicit `Key{Tenant, Conversation}`, hashed filenames and CAS revisions. `Archive` fsyncs original history and a usable unreduced working copy *before* `Reduce` is invoked. Reduction failure preserves that archive. One pinned compactor owner prevents competing cooperating reducers. `Continue` holds revision admission across replay/coordinator execution, so stale losing revisions do not invoke the coordinator. Atomic temp-file write + file fsync + rename + directory fsync is serialized by a separate advisory flock file across processes. The fresh-process fixtures reload actual files, preserve private results and lineage, deny duplicate revisions and avoid rerunning internal tools. A post-rename fsync error is explicitly `commit uncertain`; reread the revision before retrying.

**Routing API:** `Prepare` validates complete destination scope, target capabilities, token/temperature settings and explicit affinity migration, then validates wire request construction. `Classify` uses a managed call and exact allowlisted label (never a model-supplied destination). `Candidates` bounds fan-out, selects only complete accepted results, cancels losers and waits for their functions to end; every logical outcome is observed. `Reroute` rejects committed delivery before dispatch. `CacheKey` requires resolved tenant/conversation, account, endpoint, version and state revision, hashes messages/tools/settings and requested/served target scope, and excludes transient logical lineage/purpose. There is no cache implementation. `Affinity` requires explicit portable migration; provider-held state cannot change provider/model/account/endpoint/protocol/version.

### Correction round 2: wire validation and late cancellation

The manager's four verified findings and additional usage/settings checks are addressed within Group C ownership:

- `ai/wire.go` validates recognized wire-field types before convenience getters: nested objects/arrays (including null elements), roles, function/name/argument fragments, usage and envelope metadata. Anthropic ordinary responses now require `type: message`, `role: assistant` and a non-null supported terminal `stop_reason`; tool calls require `tool_use` and object inputs. Synthetic `Response` construction still permits omitted stop/envelope fields through `Encode`; this convenience does not weaken `Decode`. Stream start envelopes and text/input deltas receive corresponding validation.
- Chat streams reject unknown choice/delta/tool/function semantics instead of flattening them. Accepted `system_fingerprint` and `service_tier` fields remain in `Response.Extra` and same-wire JSON encoding; cross-wire and synthetic-stream conversion reject those nonportable fields. `Response.Events` retains detached buffered event evidence, including on semantic decode errors returned by `DecodeBuffered`. It is evidence, not an implicit stream-passthrough or permission to ignore decode errors; encoders still generate from validated semantic state.
- `Session.Call` rechecks cancellation immediately before successful return, after observation/output accounting. The observer still receives the original inference outcome; deadline expiration during observation cannot turn into client-visible success.
- Chat encoding clears old usage counters, removes the old usage object when empty, and recomputes `total_tokens` only when both new counters are known (overflow rejected). Nil versus measured zero remains distinct. Nonfinite temperatures are rejected by request encoding; they cannot be silently omitted through an unchecked insertion helper.

Regression evidence added in `ai/correction_test.go`: `TestWireEnvelopeRejectsBeforeOwnedTools` (invalid Anthropic envelopes/inputs cause zero owned-tool effects), `TestBufferedStreamUnknownEvidenceAndMetadata` (unknown fields at root/choice/delta/tool/function nesting, retained event evidence and metadata conversion restrictions), `TestMalformedKnownWireFields` (Chat ordinary/SSE known types, Anthropic start envelopes and text/input fragments), `TestObservationDeadlinePreventsSuccess` (direct Session and text-only Coordinator), and `TestUsageEditsAndNonfiniteSettings` (nil/zero/replaced counters, consistent totals, NaN/infinities). Two earlier valid Anthropic opaque/reordered fixtures now include the required assistant-message envelope; their opaque-preservation assertions are unchanged.

### Honest limitations / newly discovered cases

- This is intentionally a narrow semantic subset: one choice, text and ordinary function/tool calls with usable complete JSON, no multimodal importer, signed reasoning conversion, server tools, opaque provider references, provider-managed continuation, nonempty initial streamed tool input or reordered text-after-tool blocks. Raw same-wire Documents / unchanged passthrough remain available. Anthropic system messages in constructed histories are rejected (use explicit same-wire document editing); unsupported temperatures/settings/capabilities are rejected rather than guessed. Routing preparation supports the two built-in protocols; a new protocol can implement the interfaces and its own preparation.
- Streams are buffered. Unknown SSE data is retained for explicit unchanged handling but semantic conversion refuses unknown state. This is not live latency/backpressure/client-disconnect certification. Model `length` / `max_tokens` completion is explicitly an error, not a final successful answer.
- Session counters are in-process, cumulative for that Session; only Turn rounds/lineage and application history are persisted here. A caller must inherit authoritative host limits across restarts and set a root deadline if a series of client handoffs needs one total wall-clock bound. Output accounting bounds returned material, not arbitrary allocation inside trusted bridge/tool/observer code. Disabling a bound does not disable cancellation.
- Cancellation is cooperative. A trusted function that ignores context keeps capacity charged and selection/coordination waits for it; no detached work is misreported as stopped. There is no R41 sandbox/forced-stop claim. An error/crash during an external tool effect can be ambiguous; revision CAS does not make external effects exactly once.
- Atomic-file topology requires a local filesystem supporting flock, atomic same-directory rename and file/directory fsync, on Linux/macOS/FreeBSD (Linux exercised). Other platforms explicitly reject mutation. No NFS, multi-host, database, encrypted-at-rest, retention/GC, lock-fairness or power-loss fault-injection claim. Archives and the serialized file are bounded; there is no archive eviction that could silently lose originals. Existing storage directories must already be trusted/private.
- Unknown and measured-zero usage remain distinct, but this package does not invent missing provider usage, aggregate prices, certify token counters or replace original host attempt evidence. The example observer is optional at the API boundary; real mandatory observation is the managed host's responsibility.
